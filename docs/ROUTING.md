# Routing, Outbounds и GeoFiles

Эта инструкция относится к SG-Gateway 23.01 и описывает серверную маршрутизацию: клиент подключается к SG-Gateway обычным способом, а решение о конечном выходе принимается на сервере.

## Что делает Routing

Routing отвечает на два вопроса: какой трафик совпал с правилом и через какой выход этот трафик отправить.

Схема: Клиент → SG-Gateway → правило Routing → выбранный outbound → Интернет.

Доступные выходы:

- SG-Gateway · IPv4 — публичный IPv4 сервера;
- SG-Gateway · IPv6 — публичный IPv6 сервера;
- WARP · IPv4 — Cloudflare WARP IPv4;
- WARP · IPv6 — Cloudflare WARP IPv6;
- внешний SOCKS5 — proxy, добавленный в Outbounds;
- внешний HTTP CONNECT — proxy, добавленный в Outbounds;
- Outbound group — группа Round Robin, Random или Failover;
- Заблокировать — Xray не выпускает совпавший трафик наружу.

IPv4 и IPv6 являются отдельными действиями. SG-Gateway не выполняет скрытый fallback между семействами адресов.

## 1. Самый простой сценарий

Если нужна обычная работа без специальной маршрутизации:

1. Откройте Routing.
2. В Базовая схема выберите Обычный доступ · SG-Gateway · IPv4.
3. Нажмите Проверить.
4. Дождитесь статуса Проверка пройдена.
5. Нажмите Применить.

Кнопка Проверить не меняет рабочую конфигурацию. Она строит candidate и проверяет будущий Xray config. Рабочая маршрутизация меняется только после Применить.

## 2. Базовые схемы

### Обычный доступ · SG-Gateway · IPv4
Остальной трафик идёт через IPv4 сервера.

### Блокировка рекламы
Рекламная категория отправляется в Заблокировать, остальной трафик остаётся на SG-Gateway IPv4.

### Privacy · реклама + трекеры + угрозы
Использует расширенный набор категорий фильтрации, если они присутствуют в текущих GeoFiles.

### Strict · усиленная фильтрация
Более строгий вариант фильтрации. Перед применением смотрите блок Фактические правила candidate.

### Ресурсы, заблокированные в РФ через WARP · IPv4
Категория заблокированных ресурсов идёт через WARP IPv4. WARP IPv4 должен быть готов.

### Весь интернет через WARP · IPv4
Остальной трафик направляется через WARP IPv4. Локальная сеть остаётся отдельным правилом.

### Пользовательская схема
Используется для ручного назначения действий и собственных доменов/IP. Любое ручное изменение основных правил переводит конфигурацию в пользовательский режим.

## 3. Основные правила

### Локальная сеть
Предназначена для частных адресов, домашнего роутера, NAS, принтеров и других локальных ресурсов. Для неё доступны SG-Gateway IPv4, SG-Gateway IPv6 и Block.

### Ресурсы, заблокированные в РФ
Использует категорию из фактически установленных GeoFiles. Её можно отправить через WARP, внешний proxy, outbound group или Block.

### Реклама
Назначает действие рекламной категории текущего набора GeoFiles. Типовой вариант: Реклама → Заблокировать.

### Остальной трафик
Финальное правило. Оно применяется, когда ни одно более специфичное правило выше не совпало.

Пример схемы:

Заблокированные ресурсы → France
Реклама → Block
Остальной трафик → SG-Gateway IPv4

## 4. Порядок правил

Xray обрабатывает правила по порядку. Первое подходящее правило определяет маршрут.

Перед применением SG-Gateway показывает Фактические правила candidate. Проверяйте номер правила, название, найденную GeoSite/GeoIP-категорию, конечное действие и отметки о пропущенных или недоступных правилах.

Финальное правило Остальной трафик должно оставаться последним.

## 5. Пользовательские правила

Откройте блок Пользовательские правила. Сейчас отдельные редакторы собственных доменов/IP есть для SG-Gateway IPv4, SG-Gateway IPv6, WARP IPv4, WARP IPv6 и Заблокировать.

Для каждого действия есть поля Домены и IP и подсети. Одна запись — одна строка.

Поддерживаемые доменные формы Xray: full:example.com, domain:example.com, regexp:, keyword: и geosite:. Без префикса SG-Gateway использует domain:.

Примеры доменов: youtube.com, googlevideo.com, domain:netflix.com, full:api.example.com.

Примеры IP/CIDR: 1.1.1.1, 8.8.8.8, 203.0.113.0/24, 2001:db8::/32.

Семейство адреса должно соответствовать выбранному выходу. IPv4 и IPv6 не подменяют друг друга автоматически.

## 6. Как добавить внешний сервер

Откройте Outbounds → External outbounds.

Заполните Название, Тип, Host, Порт и при необходимости Логин/Пароль. Поддерживаются SOCKS5 и HTTP CONNECT.

После Добавить выход SG-Gateway сохраняет outbound, не выводит пароль обратно в интерфейс, строит полный Xray candidate, запускает проверку конфигурации и применяет изменение только после успешной проверки. При ошибке состояние откатывается.

После успешного создания внешний outbound появляется как вариант действия в основных правилах Routing.

Пример: France · SOCKS, host fr-proxy.example.net, порт 1080.

## 7. Outbound Groups

Если внешних выходов минимум два, откройте Outbounds → Outbound groups.

### Round Robin
Распределяет новые соединения между выбранными выходами по очереди. Используйте, когда выходы равноправны и требуется распределение нагрузки.

### Random
Для новых соединений выбирает один из членов группы случайным образом.

### Failover
Требует ровно два выхода: первый основной, второй резервный. Xray Observatory проверяет основной outbound. Если основной считается недоступным, balancer использует резервный fallbackTag.

Пример: France Primary + Germany Backup → группа EU Backup · Failover. В Routing можно выбрать EU Backup как действие.

Failover предназначен для доступности, а не для одновременного распределения нагрузки.

## 8. Практические примеры

### A. Реклама блокируется, остальное напрямую
Реклама → Заблокировать
Остальной трафик → SG-Gateway IPv4

### B. Заблокированные ресурсы через WARP
Ресурсы, заблокированные в РФ → WARP IPv4
Реклама → Заблокировать
Остальной трафик → SG-Gateway IPv4

### C. Весь основной интернет через внешний proxy
Создайте France в Outbounds, затем выберите Остальной трафик → France.

### D. Основной proxy + резервный
Создайте France и Germany, затем EU Backup → Failover, где France основной, Germany резервный. В Routing выберите нужное правило → EU Backup.

### E. Собственные домены через внешний proxy
В 23.01 пользовательский редактор собственных доменов имеет отдельные вкладки только для SG-Gateway/WARP/Block. Отдельной вкладки France для произвольного списка доменов пока нет. Внешний outbound можно назначить основным категориям Routing и Остальному трафику. Это текущее ограничение UI.

## 9. WARP

WARP создаётся и обслуживается в Outbounds. WARP IPv4 и WARP IPv6 — независимые действия. Если готов только WARP IPv4, WARP IPv6 не должен использоваться и система не должна тайно переключать семейство.

## 10. IPv4 и IPv6

SG-Gateway IPv4 не равен SG-Gateway IPv6. WARP IPv4 не равен WARP IPv6.

Если выбрано IPv4-действие, SG-Gateway не должен автоматически выходить через IPv6 при проблеме IPv4. Для IPv6 действует то же правило в обратную сторону.

## 11. GeoFiles

Routing использует связанную пару geoip.dat + geosite.dat. Эти файлы проверяются и применяются вместе.

Откройте Routing → GeoFiles, выберите источник и нажмите Проверить источник. На этом этапе рабочие GeoFiles не меняются.

После успешной проверки нажмите Обновить GeoFiles. SG-Gateway готовит пару отдельно, читает категории, пересобирает системную часть Routing, сохраняет пользовательские правила, проверяет полный будущий Xray config, создаёт backup и только затем переключает рабочие файлы. При ошибке выполняется rollback.

Если пользовательское правило требует отсутствующую категорию, применение должно остановиться, а не удалить правило молча.

## 12. Проверить → Применить

После любого изменения используйте один порядок:

1. Внести изменения.
2. Нажать Проверить.
3. Прочитать Фактические правила candidate.
4. Убедиться, что категории найдены.
5. Убедиться, что каждый rule указывает на ожидаемый outbound.
6. Нажать Применить.
7. Проверить реальный трафик.

Если после проверки вы снова изменили форму, выполните Проверить ещё раз.

## 13. Rollback

Если доступен backup Routing, кнопка Откатить возвращает предыдущие правила. После отката снова проверьте фактический трафик.

## 14. Удаление внешнего outbound или группы

SG-Gateway блокирует удаление объекта, если он используется активным Routing.

Правильный порядок: заменить outbound/group в Routing → Проверить → Применить → вернуться в Outbounds → удалить объект.

Если outbound входит в группу, сначала измените или удалите группу.

## 15. Как проверить, что маршрут реально работает

После применения проверьте:

1. Фактические правила Routing.
2. Наличие нужного outbound/group в Outbounds.
3. Состояние Xray в System.
4. Реальный внешний IP через сервис проверки IP.
5. Конкретный сайт или категорию, для которой создавалось правило.

Для Failover отдельно проверьте работу при доступном основном proxy и при его недоступности.

## 16. Типовые ошибки

### Вариант выхода серый
Соответствующая capability не готова: нет публичного IPv6, WARP IPv4/IPv6 не готов или выключен.

### Внешний outbound не появился
Если Xray candidate не прошёл проверку, создание должно быть отменено.

### Нельзя удалить outbound
Он используется активным Routing либо входит в группу.

### Нельзя удалить группу
Группа используется активным Routing. Сначала переведите правила на другой выход и примените Routing.

### GeoSite/GeoIP категория не найдена
Текущая пара GeoFiles не содержит нужную категорию. Выберите совместимый источник или исправьте правило.

### После изменения ничего не поменялось
Проверьте полный цикл: изменить → Проверить → Применить. Сама проверка рабочую конфигурацию не меняет.

### Сайт идёт не через тот выход
Проверьте фактический порядок правил. Более раннее правило может перехватывать поток.

## 17. Что хранится на сервере

External Outbounds являются серверной настройкой SG-Gateway. Клиенту не требуется знать внутренний SOCKS/HTTP proxy: точкой подключения для него остаётся SG-Gateway.

Чувствительные данные proxy хранятся на сервере; пароль не возвращается обратно в web UI после сохранения.

## 18. Рекомендуемый безопасный порядок

1. Создать external outbounds.
2. Проверить, что Xray принял их.
3. При необходимости создать group.
4. Открыть Routing.
5. Назначить один тестовый rule.
6. Проверить candidate.
7. Применить.
8. Проверить реальный внешний IP/сайт.
9. Только затем добавлять остальные правила.

Перед большой перестройкой критичного сервера создайте Full Backup в Maintenance.

## Короткая памятка

Outbounds = куда можно отправить трафик.
Routing = какой трафик куда отправить.
GeoFiles = готовые категории доменов/IP.
Block = не выпускать трафик.
Failover = основной внешний выход + резервный.

Рабочий цикл: создать выход → выбрать правило → Проверить → посмотреть candidate → Применить → проверить реальный трафик.
